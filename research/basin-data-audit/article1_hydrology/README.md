# Гидрологическая база статьи: первая сборка, 03.11.2026

**Продолжение:** [Markala → Office du Niger](markala/README.md) — документальная схема водоснабжения и четыре реально полученных ряда SIEREM (2 164 месячных значения), с проверкой размерностей, пропусков и конфликтов координат. Ниже сохранён отчёт первой сборки; его нулевой счётчик расходов относится к прежней таблице, а не к новым файлам `markala/outputs/`.

**Статус: пригодна для подготовки гидрологического пилота, ещё не для оценки дефицита подачи воды.**
Сборка опирается на Research Compass v1.3. Основная магистерская сохраняет кукурузу, сорго и рис; здесь подготавливается дополнительная проверка речного водоснабжения конкретных оросительных систем.

Присоединение осадков означает лишь административный контекст. Гидропосты не соединены со схемами по ближайшей точке: гидросвязность пока не установлена.

## Проверки и найденные проблемы

- Полностью перечитаны четыре исходных климатических файла: **133 584 строки, 253 района, 528 месяцев**. Проверены уникальность ключей, календарная полнота, конечность и неотрицательность значений, диапазон бассейновых долей, согласованность числа пикселей и статуса. Новая проверка не повторяет независимую растровую валидацию предыдущего этапа.
- Все 5 808 выбранных строк побитово совпадают по значениям текстовых полей с соответствующими строками CSV-источника. Код тестов отдельно сверяет таблицу SQLite с CSV.
- Метаданные постов повторно сверены с извлечённым текстом обеих таблиц полного PDF. Исправлены две ошибки предварительной выписки: **Samandeni −4.47°, Nobere −1.18°**. Повторное получение изображения страниц/PDF вернуло 403; визуальная сверка и проверка по официальному каталогу остаются открытыми. Координаты нельзя считать точными WGS84-точками для привязки к руслу.
- У **Pwalagu и Lawra** указанные проценты пропусков отличаются более чем на 0.5 процентного пункта от расчёта по полным годам указанного периода. Pwalagu начинается в 1975 г., хотя заголовок таблицы говорит о 1979–2013. Это флаги для уточнения периода/знаменателя, **не доказательство ошибки авторов**. Исходные цифры сохранены; покрытие не исправлено предположениями.
- Високосные годы, перевод среднего расхода в объём и отказ от такого перевода при неполном месяце проверяются тестами. Пропуски никогда не заменяются нулями.

## Единицы и правила объединения

| Поля | Единица / тип | Как использовать |
|---|---|---|
| `rainfall_mm_month` | мм накопленного слоя за календарный месяц | Суммировать месяцы для слоя за окно; не умножать повторно на число дней. Это не мм/сут и не объём |
| `year`, `month` | календарные целые | CHIRPS: 1981–2024, 1–12; привязка к урожаю требует отдельного сезона |
| `latitude_deg`, `longitude_deg` | градусы | Географические координаты из статьи; datum не указан; порядок широта/долгота явный |
| `upstream_area_km2` | км² | Литературная площадь водосбора поста, не площадь орошения. Для м² ×1 000 000 |
| `missing_count_reported` | дни или месяцы | Единица определяется `time_step_reported`, не смешивать между таблицами |
| `missing_pct_reported` | % | 11.1 означает 11.1%, не долю 0.111; знаменатель требует уточнения |
| `dominant_share` | безразмерная доля 0–1 | Пространственная доля бассейна в предыдущем GIS-анализе, не доля орошения |
| `valid_grid_cell_centres` | число пикселей | Поддержка пространственного среднего; не площадь |
| `discharge_m3_s` | м³/с | Зарезервировано для расхода; таблица пуста, не нулевой расход |
| `interval_start`, `interval_end_exclusive` | ISO-даты | Интервал [начало, конец); определения времени источника ещё нужно проверить |
| `valid_days`, `expected_days` | дни | Покрытие исходного месячного расхода; не устанавливать автоматически равным длительности месяца |
| `aggregation` | категория | Нужно отличать среднее за интервал от мгновенного значения |
| `observation_or_model` | категория | Наблюдения и модельные оценки хранить раздельно |
| ID, коды, URL, статусы | строки | Неизвестные внешние ID пусты; `UNKNOWN` не означает отсутствие явления |

Для полного среднего расхода за интервал: `V_m3 = Q_mean_m3_s × seconds_in_interval`. Среднее GRDC за месяц может опираться на **20** суточных значений; это не полное наблюдение месячного объёма. При неполном покрытии функция отказывается считать полный наблюдённый объём. Для будущего дефицита необходимо интегрировать `max(Q_required − Q_available, 0)` по времени; разность м³/с сама по себе не является дефицитом в м³. Перевод объёма в слой требует соответствующей площади: `depth_mm = volume_m3 / area_m2 × 1000`; для гектаров `area_m2 = area_ha × 10000`.

## Источники и происхождение

- Климат и кандидаты: git commit `3284f1d571b7b3709582f7022d2b22440da428a1` этого репозитория. Используются четыре `../results/climate_panel/chirps_v3_district_monthly_*.csv` и `../institutions/irrigation_schemes_water_source_evidence_v1.csv`. Их SHA-256 и размеры сохранены в `outputs/provenance.json`. Исходные растры заново не скачивались; прежняя растровая provenance остаётся в исходном каталоге.
- Gebrechorkos et al. (2022), *Variability and changes in hydrological drought in the Volta Basin, West Africa*, [DOI](https://doi.org/10.1016/j.ejrh.2022.101143), [полный текст](https://eprints.soton.ac.uk/467633/1/1_s2.0_S2214581822001562_main.pdf), таблицы 1–2, печатные стр. 5–6. Перенесены фактические метаданные, не временные ряды. `VOLT_T1_01` и подобные — **наши внутренние ID**, не номера GRDC. Периоды характеризуют использованный авторами набор, не сегодняшнюю доступность архива.
- [GRDC: портал и условия](https://grdc.bafg.de/data/data_portal/), проверено 03.11.2026: данные запрашиваются через портал; исходные ряды нельзя публично перераспространять. В репозиторий не включать полученные по запросу наблюдения без соответствующего разрешения. Публичные производные результаты отделить от локального хранилища исходных рядов.

## Следующая закупка данных и критерии готовности

| Приоритет | Что получить | Что считается достаточным |
|---|---|---|
| 1: Office du Niger / Markala | Точки водозабора, границы реально обслуживаемых полей, схема каналов и узлов регулирования | Первичный источник, CRS, дата действия границ; GIS-проверка направления речной сети |
| 2: водоснабжение | Суточный приток и/или расходы у водозабора, отбор в каналы, уровни и правила работы | Файл с единицами, временем, флагами качества и понятным владельцем; расход реки не подменяет подачу в канал |
| 3: независимая гидрология | Официальные ID и ряды постов Нигера; по Вольте — сверка 39 кандидатов с каталогом GRDC/национальным оператором | Выбор поста по гидросвязности, регулирующим сооружениям и перекрытию лет; не по одному расстоянию |
| 4: потребность | Орошаемая площадь по годам/сезонам, календарь риса, ET/ET0, потери/эффективность | Нельзя использовать MIRCA 2020 как постоянную фактическую площадь всех лет; учитывать перколяцию и режим затопления риса |
| 5: экономический результат | Урожай/площадь/затраты или цена на уровне той же системы и сезона | Не выдавать районный смешанный ряд за урожай орошаемых полей |

До прохождения 1–3 нельзя оценивать надёжность подачи или её трансграничный механизм. Каталог Вольты — резерв для проверки наблюдений, а не решение о переносе пилота из Нигера. Указанная в прежнем общем реестре стадия CHIRPS `FOUR_MONTH_PILOT_DOWNLOADED_VALIDATED` устарела; для текущего объёма использовать Compass v1.3 и этот QA.

## Воспроизведение

Из корня репозитория, Python 3.10+ без дополнительных пакетов:

```bash
python research/basin-data-audit/article1_hydrology/build.py
python research/basin-data-audit/article1_hydrology/test_database.py
```

Скрипт пересоздаёт только `article1_hydrology/outputs/`. Проверка provenance подтверждает соответствие текущих входов записанным хешам; это не проверка подлинности первичного растра. Перед обновлением источников пересмотреть период и ожидаемые размеры панели. История git хранит предыдущие версии provenance и результатов.
